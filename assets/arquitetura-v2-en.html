Inverted Agentic Orchestration

ARCHITECTURAL PATTERN · realized in this repository as Harness.Engine + Flows.Development

The IDE agent (Copilot · Devin · Claude Code · Codex) acts as an operational interpreter: it runs the harness, reads the next instruction from stdout, follows the requested contract, and returns a structured response. The harness — not the model — decides the next state, validates responses, persists state on disk, and records the execution trace.

THE PATTERN — Inverted Agentic Orchestration
“Agent orchestration is inverted: a deterministic state machine in code — not the model — decides the next state.”

Intent — README.md

USE THIS PATTERN WHEN
  • the workflow must be reproducible, auditable, or resumable;
  • execution spans multiple steps and may survive context resets;
  • the agent must follow structured contracts on every turn;
  • the domain requires deterministic validation before advancing;
  • different IDE agents must drive the same protocol;
  • step, time, or cost ceilings must be enforced by the system;
  • workflow business logic must be testable outside the model.
AVOID IT WHEN

The task is a single generation with no state, return contract, or real need to govern multiple iterations. In that case, the harness only adds a layer without a corresponding benefit.

BENEFITS
  • the workflow is testable as ordinary code;
  • the state sequence no longer depends on model memory;
  • another agent can resume execution with the same artifacts;
  • protocol errors are detected early and handled explicitly;
  • step, cost, and timeout guards reduce runaway loops;
  • the persisted trace provides evidence for audit and later evaluation;
  • different adapters share the same runner and contract.
COSTS / TRADE-OFFS
  • the project must maintain a state machine and JSON contracts;
  • each new domain requires its own tasks, validations, and prompts;
  • the experience depends on the agent replying only in the requested format;
  • very simple workflows may not justify the harness layer.

Definition: the IDE agent performs the actions, but workflow policy lives outside the agent, in a deterministic harness that emits one instruction at a time, validates responses, and persists state in the filesystem. The "think → act → observe" loop runs in the driver; the harness is single-shot per turn. The state machine decides the next command and emits stop when all features pass.

OFFICIAL FLOW — feature-oriented development

Flows.Development

Incremental implementation through 8 registered commands: after start → plan, the harness runs bearings → smoke → pick internally. The driver normally only implements; verify and handoff are automatic when possible and become repair turns only when deterministic execution fails.

start plan bearings smoke pick implement verify* handoff*

* registered for compatibility; the normal path resolves whatever it can internally.

Development Agent

The custom agent uses .harness/inbox.json, runs ./run-development.sh without arguments, and resets context per feature.

PER-FEATURE CYCLE — four recurring beats

Plan

start → plan: creates init.sh, defines the target, verification command, and feature list.

once per run

Reorient

bearings → smoke → pick: the harness reads the filesystem, runs smoke, and selects the next pending item without spending a driver turn.

clean context

Deliver

implement edits the feature; the harness tries to verify automatically with verify-feature.sh or the configured verify_cmd. On success, it performs auto-handoff (commit + progress.txt) without an extra turn; on failure, the driver receives a repair task.

commit + progress.txt per item

Stop

When FeatureStore.AllPassing() is true, stdout becomes only stop.

no manual decision

Guardrails MaxFeatures = 10, StepsPerFeature = 8, StepBudget = 88.
Corrective loop FAIL in verify does not change the feature; it returns to repair of the same item.
Dependency graph dependsOn validates cycles in plan; pick only releases features whose dependencies have Passes = true — with no ready candidate, it ends with stop.
